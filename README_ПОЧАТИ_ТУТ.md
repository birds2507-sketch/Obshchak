# ОБЩАК — Android v2.0 TEST

**Що це:** вихідний проєкт окремого Android-застосунку (Java, Android Studio) + оновлений Google Apps Script. Дані залишаються у вашій Google Таблиці, чеки — у приватній папці на Google Drive. **Власний сервер не потрібний.**

> ⚠️ **Це вихідний проєкт, НЕ готовий APK.** У середовищі підготовки немає Android SDK/Gradle, тому APK тут не скомпільовано і на фізичному Android не перевірено. Для отримання APK потрібно зібрати проєкт у Android Studio або через доданий workflow GitHub Actions. Не використовуйте реальні гроші до успішних тестів.

## Що реалізовано

- Окремий Android-інтерфейс із входом, загальним балансом, приходом і витратами, історією, чеками, коментарями, учасниками, виборами та PDF-звітами.
- Один спільний баланс **готівка + банк**; метод внеску вказується у приході.
- Збирає та записує фінансові операції тільки касир; інші бачать історію, чеки, коментарі та звіти. Вибори — від 3 учасників, більшість із фактичного складу до 10.
- Камера та галерея/PDF. **Оригінальні фото** копіюються в приватну пам'ять застосунку. Для передачі в Google Drive робиться окрема оптимізована копія (не більше 2 МБ).
- Заповнення витрати зберігається у локальній чернетці після кожного редагування. Фото чи вибір галереї **не очищує поля**.
- Касир може зберегти прихід/розхід **без інтернету**. Операції і фото в черзі SQLite із показом статусу.
- WorkManager після появи інтернету сам повторює передачу. Щоб не з'явилися дублікати після обриву мережі, **сервер використовує ідентифікатори операцій та чеків**.
- Фоновий дозвіл на передачу діє до **30 днів**, зберігається зашифрованим через Android Keystore. Після закінчення / зміни пароля потрібне повторне підтвердження касира. Сам пароль у застосунку не зберігається.
- PDF без фотографій чеків, але з позначками їхньої наявності.
- Повна вебверсія залишена доступною окремою кнопкою для додаткових адміністративних операцій.

## Послідовність встановлення

### Крок 1 — оновити Google Apps Script

1. **Зробіть копію Google Таблиці** «ОБЩАК — база даних» перед оновленням. Не видаляйте старі файли на Drive.
2. У своєму **існуючому** Google Apps Script-проєкті `ОБЩАК` відкрийте `Code.gs` та **повністю замініть його вміст** файлом `gas/Code.gs` із цього архіву.
3. Аналогічно оновіть `Index.html` із `gas/Index.html`. Це вебверсія з додатковим збереженням введених полів форми.
4. Збережіть проєкт (Ctrl+S). **НЕ запускайте `initializeObshchak` і НЕ запускайте `setupOwner_` повторно!** Вони лише для нової пустої бази.
5. **Розгорнути → Керування розгортаннями → Редагувати → Нова версія → Розгорнути.** Користуйтеся тим самим URL `/exec`, якщо редагуєте наявне розгортання.
6. Скрипт автоматично створить службовий аркуш `DeviceTokens` під час першого входу касира з Android. Саму стару таблицю **не переписуватиме**.

### Крок 2 — зібрати Android APK

**Варіант А: Android Studio на Windows/ПК**

1. Встановіть Android Studio (офіційний сайт: https://developer.android.com/studio), Android SDK Platform 35, Build-Tools і JDK 17.
2. Відкрийте теку `android/` як проєкт (**File → Open**).
3. Потрібні Android Gradle Plugin **8.9.2**, Gradle **8.11.1**, AndroidX WorkManager **2.12.0**. Якщо Android Studio вимагає файл Gradle Wrapper JAR, виконайте `gradle wrapper --gradle-version 8.11.1` з уже встановленим Gradle або використайте варіант Б нижче. Бінарний JAR навмисно не вкладено.
4. Виконайте **Build → Build APK(s)**; після успішного збирання шукайте `android/app/build/outputs/apk/debug/app-debug.apk`.

**Варіант Б: GitHub Actions (зручно без налаштованого Android SDK на своєму ПК)**

1. Створіть **приватний** репозиторій GitHub.
2. Завантажте до нього **вміст кореневої папки цього архіву**, зокрема `android/` і `.github/workflows/android.yml`.
3. У вкладці **Actions → Build test Android APK → Run workflow** дочекайтеся успішного результату.
4. У розділі **Artifacts** завантажте `OBSHCHAK-android-debug-apk`, розпакуйте; всередині буде `app-debug.apk`.

**Увага:** workflow теж не був запущений у цій розмові. Він є заготовкою автоматичного збирання для першого реального тесту.

### Крок 3 — перший вхід на Android

1. На телефоні встановіть **свій** APK (на Android може знадобитися дозволити встановлення з обраного джерела).
2. Відкрийте «ОБЩАК». Перший раз введіть **своє посилання Google Apps Script `/exec`**.
3. Введіть особистий логін касира (`kasyr`, якщо не змінювали) та пароль. Якщо це тимчасовий пароль, встановіть новий.
4. Застосунок прив'яже до касира дозвіл фонової синхронізації; в налаштуваннях каси нових паролів вводити для кожної витрати не треба.
5. Інших учасників касир додає поступово (1–10). Вхід за особистими логінами.

## Головний тест роботи без інтернету

1. Увійдіть як касир, відкрийте **«− Витрата»**.
2. Уведіть дату, суму, категорію, призначення; увімкніть **режим польоту**.
3. Натисніть **«📷 Сфотографувати»** або **«📎 З галереї / PDF»**. Повернувшись до форми, переконайтеся, що **сума, дата, призначення не зникли**.
4. Натисніть **«Зберегти на телефоні й синхронізувати»**. У черзі буде статус «Очікує інтернету».
5. Увімкніть інтернет. Android WorkManager запустить передачу, коли система дозволить. За бажанням натисніть **«Спробувати синхронізувати»**.
6. Перевірте статус **«Завантажено в Google»**, один запис витрати у вебверсії, а також чек на Google Drive. Кілька повторних спроб не повинні створювати дублікати.

## Обмеження, важливі для безпеки

- Локально збережені фотографії містяться у **приватній пам'яті застосунку** (не автоматично в галереї). Видалення застосунку / очищення його даних може назавжди видалити несинхронізовані чеки. Не робіть цього.
- До статусу **«Завантажено»** інші учасники не бачать нову витрату або чек.
- Якщо пристрій **залишався офлайн більше 30 днів**, змінилися права касира чи пароль, потрібна повторна авторизація та кнопка **«Оновити дозвіл фонової синхронізації»**. Черга й фотографії зберігаються.
- WorkManager не гарантує передавання в ту саму секунду після появи мережі; система Android може відкладати завдання через батарею або обмеження фонових процесів.
- **Справжні push-повідомлення на заблокований телефон не реалізовані** у тестовій Android v2.0. Є вкладка подій / онлайн-активність.
- Адміністративне блокування користувачів, скидання паролів та акт передачі каси за необхідності зручно виконати у вебверсії (кнопка «Відкрити повну вебверсію»). Там потрібен окремий вхід через той самий логін.
- Це **тестовий вихідний код**. Він ще не зібраний та не перевірений на фізичному Android. Не вносьте реальні суми до завершення перевірки.
- Google Apps Script має квоти. Власник Google-таблиці технічно може редагувати її напряму, отже «незмінність» записів забезпечує застосунок, а не незалежний аудиторський реєстр.
- Бажано створювати резервні копії Google Таблиці й чекам на Drive перед кожним оновленням.

## Структура архіву

- `android/` — вихідний Android Studio Java-проєкт, WorkManager, SQLite, камера, вхід, екрани.
- `gas/Code.gs` — Google Apps Script v2 з `doPost`, фоновими токенами, ідемпотентними операціями і чеками.
- `gas/Index.html` — вебверсія, доповнена збереженням текстових полів форми.
- `tests/test_gas_api.js` — автоматизована імітаційна перевірка API, повторів, прав та токенів.
- `.github/workflows/android.yml` — автоматичне збирання debug APK на GitHub.
- `ТЕСТ_ПЕРЕВІРКА.md` — список перевірок на телефоні.
