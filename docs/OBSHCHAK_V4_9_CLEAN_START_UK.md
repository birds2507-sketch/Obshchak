# ОБЩАК 4.9 — чиста база та перший адміністратор

> **Увага:** ці дії починають новий облік із порожніх журналів. Попередня база та стара папка чеків залишаються на Google Drive як архів; нічого не стирається безповоротно. Виконуйте тільки після завершення тестів.

## 1. Підготовка

1. На всіх телефонах припиніть тестові внески, витрати, заявки на борги й прикріплення чеків. Перевірте чергу синхронізації.
2. Відкрийте **чинний** проєкт Google Apps Script (той, до якого підключена ваша вебверсія).
3. Скопіюйте в нього з GitHub нові **gas/Code.gs** та **gas/Index.html**, повністю замінюючи вміст цих двох файлів.
4. Збережіть і оновіть **чинне** розгортання вебзастосунку: Deploy → Manage deployments → Edit → New version → Deploy. Створювати друге розгортання з новою URL не потрібно.
5. Установіть **ОБЩАК v4.9** поверх старої версії, якщо важливо спочатку перевірити інсталяцію. Після скидання на кожному тестовому телефоні потрібно очистити локальні тестові дані.

## 2. Створіть нову чисту базу

1. У редакторі Google Apps Script угорі у списку функцій виберіть **resetObshchakForCleanStart**.
2. Натисніть **Run/Виконати**. За потреби підтвердьте дозволи на Google Sheets та Drive.
3. Відкрийте **Execution log/Журнал виконання**.
4. Запишіть:
   - URL нової порожньої бази (**НОВА БАЗА ОБЩАК**);
   - URL старої бази-архіву (**АРХІВ ПОПЕРЕДНЬОЇ БАЗИ**);
   - **КОД ПЕРШОГО АДМІНІСТРАТОРА** — одноразова послідовність із 64 символів, чинна 7 днів.

**Не запускайте** функцію resetObshchakForCleanStart повторно після створення нових робочих записів. Вона створить ще одну порожню базу й залишить попередню в архіві.

Якщо код реєстрації прострочився до першої реєстрації, запустіть тільки **renewFirstAdminCode** (вона не чіпає журнали).

Для абсолютно нового проєкту Apps Script, де ще не заданий SHEET_ID, виконайте **setupOwner_** замість скидання. Вона тепер створює порожню базу без автоматичного касира.

## 3. Очистіть локальні тестові записи на телефонах

Кожен тестувальник відкриває Android → Налаштування → Програми → ОБЩАК → Пам'ять → Очистити дані. Робіть це тільки якщо локальні дані суто тестові — це зітре чернетки й не синхронізовані фото/операції саме на телефоні. Стару Google-таблицю це не змінить.

Після очищення відкрийте застосунок; якщо адреса сервера була налаштована вручну, введіть її знову через налаштування.

## 4. Перший вхід адміністратора

1. На екрані входу Android натисніть **Перший запуск · Зареєструвати адміністратора**. У вебверсії форма реєстрації з'явиться автоматично.
2. Введіть одноразовий код із Execution log, ім'я, особистий латинський логін і PIN із **4 цифр** або довгий пароль.
3. Повторіть PIN/пароль і зареєструйтесь.
4. Увійдіть під щойно створеним адміністратором.

Звичайні прості PIN (0000, 1234, 5618 тощо) заборонені. Код реєстрації після першого використання більше не приймається.

## 5. Створіть касира та решту користувачів

- Розділ **Учасники та доступ** (Android: ☰ → Учасники; веб: Користувачі).
- Адміністратор натискає **Створити користувача**, вписує ім'я й логін, а для першого касира обирає роль **Касир**. Якщо касир уже є, обирайте роль **Учасник**.
- Для заміни касира адміністратор відкриває картку активного учасника й натискає **Призначити касиром**. Попередній касир стає звичайним учасником; фактичні кошти потрібно звірити окремо.
- **Змінити логін** можна для активних облікових записів. Ця дія змушує користувача знову ввійти в застосунок.
- **Вилучити учасника**: адміністратор вводить його логін для підтвердження. Вилучений користувач одразу втрачає доступ; ім'я та ID зберігаються в архіві, щоб не порушити зв'язки із внесками, чеками та аудитом. Активного касира спочатку потрібно змінити. Учасника з відкритим боргом або сторнуванням вилучати не можна.

## 6. Початок реального обліку

Коли касир з'явився, він відкриває вебверсію → Операції й вносить фактичний **початковий залишок** до першої операції. Якщо грошей немає — залиште нуль та починайте з першого внеску. У новому журналі будуть нуль внесків, нуль витрат, нуль боргів і нуль сторнувань до першого запису.

Нагадування: зберігайте архів тестової бази й фото чеків на Drive до того, як переконаєтеся, що нова система успішно працює.

> Примітка: внутрішні функції з завершальним `_` (наприклад, `resetObshchakForCleanStart_`) не відображаються в меню Google Apps Script. У списку запускайте **resetObshchakForCleanStart** без підкреслення. Такий видимий виклик додано до `gas/Code.gs`.
